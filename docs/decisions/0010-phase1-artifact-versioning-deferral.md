# ADR-0010: INV-10 の `version` と INV-14 を Phase 2 発効とする

## Status

Accepted (2026-09-04)

## Context

`docs/invariants.md` の INV-10 は「すべてのArtifactは `schema_name` と
`schema_version`、および同一論理成果物内での単調増加 `version` を持つ」と定めている。
INV-14 は「Upload処理はidempotentである」と定めている。

Phase 1 の実装はどちらも**部分的にしか満たしていない**:

- `artifact_metadata` に `version` 列は無い。同一性は content-addressed な
  オブジェクトキー（`artifacts/{episode_id}/{artifact_type}/{sha256}.json`）と
  `UNIQUE(episode_id, artifact_type, sha256)` で表現している
- upload 工程そのものが存在しないので INV-14 は対象コードを持たない

commit 104153b は、この食い違いを**不変条件の本文ではなく「機械検査」欄の
括弧書き**で処理した（「`version` 列は Phase 2」「未検査」）。
これは AGENTS.md §6（不変条件の変更はADR先行）を経ずに不変条件を
事実上ダウングレードした形であり、手続き上の欠陥である。
不変条件が「今は半分だけ有効」という状態を、読み手が本文から判断できない。

## Decision

**INV-10 の `version` 要件と INV-14 を、Phase 2 発効として本文に明記する。**

- INV-10 の本文を2段に分ける:
  - **Phase 1 から有効**: すべての Artifact が `artifact_type` と `schema_version` を持ち、
    スキーマ検証を通ること（機械検査あり）
  - **Phase 2 発効**: 単調増加 `version` と `superseded` による世代管理
- INV-14 の本文に「upload 工程が存在する時点（Phase 2）から有効」と明記する
- 番号は再利用しない。条件を削除もしない

**Phase 2 で upload / 再生成を実装するコミットは、同時に該当検査を入れること。**
検査の無いまま INV-10 / INV-14 を根拠にした設計を積んではならない。

## Alternatives

**(a) 現状維持（機械検査欄の括弧書きで済ませる）** — 変更ゼロ。
しかし不変条件の本文が現実と食い違ったまま残り、
「設計書に書いてある ≠ 実装されている」を読み手が本文から判断できない。
このプロジェクトの事故#7・#12 と同じ形。却下。

**(b) INV-10 / INV-14 を削除し、Phase 2 で新しい番号として書き直す** —
本文と実装は一致する。しかし「番号は再利用しない／廃止した条件は削除せず残す」
という自らのルールに反する。また Phase 2 の設計を今決めることになる。却下。

**(c) Phase 1 で `version` 列と `superseded` を実装して INV-10 を満たす** —
不変条件を本当に満たせる。しかし今回の目的は
「Phase 1 を安全な基準点として固定すること」であり、
新機能の追加は目的外。世代管理の設計（保持期間、GC）も未決。却下。

## Consequences

**良い側**
- 不変条件の本文が Phase 1 の現実と一致し、読み手が本文だけで判断できる
- 「いつから有効か」が明示されたので、Phase 2 の実装者が
  検査を書くべきタイミングを取り違えない

**悪い側 / 引き受けた負債**
- **不変条件に「発効時期」という次元が入った。** 他のINVにも同じ扱いを
  求められる可能性があり、条件が読みにくくなる方向の変更である
- Phase 2 で発効させ忘れるリスクが残る。**それを検出する機械は無い**
  （「Phase 2 発効」と書かれた条件が、対象コードの出現後も未検査のままである、
  という状態を自動検出する仕組みは作っていない）
- 現在 `version` の代替である content-addressed キーは、
  「同じ内容なら同じキー」しか表現できず、**世代の順序を持たない**。
  Phase 2 で順序が必要になった時点で移行が要る

## 陳腐化条件

- upload worker を実装したとき → INV-14 の検査を同じコミットで入れ、本文の
  「Phase 2 発効」を外す
- Artifact の再生成（世代管理）を実装したとき → INV-10 について同上
